### 2026-08-13 — ELM type recommendation reconfirmed against full component list

Thomas asked, now that the full repo is visible, which ELM actually fits best. Walked every `src/core/` model and `src/tasks/` wrapper against `classify.ts`'s shape (dense precomputed 18-dim numeric evidence vector → 1-of-18 label):

- Ruled out `KernelELM` (kernel tuning surface unjustified by an already-informative low-dim vector), `DeepELM` (autoencoder pretraining is for unstructured/high-dim raw input, not a already-structured feature vector), `ELMChain`/`ELMAdapter` (nothing to chain — input is already final), `EmbeddingStore` (retrieval index, not a classifier).
- Ruled out `IntentClassifier`/`LanguageClassifier` (text-mode/tokenizer-based — wrong input mode), `AutoComplete`/`RefinerELM`/`CharacterLangEncoderELM`/`EncoderELM` (different problems entirely).
- Read `FeatureCombinerELM.ts`: confirmed it's a thin numeric-mode `ELM` wrapper with one static helper (`combineFeatures`) for concatenating two feature sources before training — functionally identical to base `ELM` for a single feature source. Noted as the natural v2 path if a future version wants to fold in more than just the evidence vector (e.g. hashed path tokens); not needed for v1.

**Verdict unchanged from 2026-08-06:** plain `core/ELM.ts`, numeric mode, `trainFromData`/`predictFromVector`/`predictProbaFromVector`. No component in the full library beats it for this specific shape.
